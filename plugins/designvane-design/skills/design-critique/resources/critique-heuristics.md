# Critique heuristics (quick reference)

1. Visibility of system status — loading, progress, confirmation always shown?
2. Match with the real world — words the user uses, not internal jargon.
3. User control — undo, back, cancel reachable from every destructive step.
4. Consistency — same action, same words, same component, everywhere.
5. Error prevention — constraints and defaults beat error messages.
6. Recognition over recall — options visible; nothing important to memorize.
7. Flexibility — accelerators for experts that never punish beginners.
8. Minimalist design — every element earns its pixels; remove one, does it break?
9. Error recovery — plain language, exact problem, exact fix, focus moved there.
10. Help — contextual, at the moment of need, shorter than the task itself.
